# ICPC C++ Snippet & Logic Design Guide

## 1. 座標系と命名規則 (Naming & Coordinates)
- **(r, c) 形式の徹底**: 
  - 数学的な `(x, y)` ではなく、行列の `(row, col)` に統一。
  - `grid[r][c]` (grid[行][列]) を絶対ルールとし、混在を排除する。
- **Pos 構造体の導入**:
  - `pair<ll, ll>` よりも `struct Pos { int r, c; };` を定義。
  - `p.r`, `p.c` と明示することで、`.first/.second` のどっちが縦か迷う時間をゼロにする。

## 2. 関数の役割と構造 (Responsibility & Structure)
- **計算と更新の分離**: 
  - 1つの関数で「最短路計算」「盤面更新」「状態変更」をすべて行わない。
- **BFS の汎用化**:
  - 「特定のカードを探すBFS」ではなく「始点から全マスへの最短距離を返すBFS」を作る。
  - 判定（カードがあるか等）は、BFSの結果を受け取った呼び出し側で行う。
- **参照渡しの管理**:
  - 引数に `&` (参照) を多用して内部で書き換えすぎると、デバッグが困難になる。状態更新は明示的に行う。

## 3. 実戦的なスニペット管理 (Pruning Snippets)
- **デバッグ出力の標準化**:
  - `privec` 等は `std::cerr` に出力するようにし、提出時に消し忘れても Presentation Error にならない工夫をする。
- **不要なテンプレートの削除**:
  - 自分の解法に不要な「二分探索テンプレ」などは、コードが長くなりバグの視認性を下げるため、必要な時だけ貼る。
