# C++ BFSにおけるコアダンプ解析と `emplace` の深掘り

## 1. 発生した問題と直接の原因
グリッド探索（BFS）において、`std::queue<std::vector<long long>>` を使用した際にコアダンプが発生した。

### 主な原因：`emplace` によるコンストラクタの誤爆
キューの要素が `vector` である場合、`q.emplace(nx, ny)` と書くと `std::vector` の以下のコンストラクタが呼ばれてしまう。
- **呼び出されたもの:** `std::vector(size_t n, const T& value)`
- **動作:** 「`nx` 個の要素を持ち、すべてが `ny` である配列」を生成。
- **結果:** 1. `nx` が巨大な場合、メモリ確保失敗でクラッシュ。
    2. `nx` が 0 の場合、空の配列がキューに入る。その後 `current[0]` にアクセスした瞬間に領域外参照でクラッシュ。

---

## 2. `push` vs `emplace` の内部動作と違い

### `push({y, x})` の動作
1. **一時オブジェクトの生成**: ローカル（スタック）に一時的な `vector` を作成。
2. **コピー/ムーブ**: キューが確保しているメモリ領域へ、そのオブジェクトをコピー（またはムーブ）して転送。
3. **破棄**: ローカルの一時オブジェクトを破棄。

### `emplace(y, x)` の動作
1. **配置new (placement new)**: キューが内部で確保済みの「未初期化メモリ領域」の住所を特定。
2. **直接生成**: その住所に対して、直接コンストラクタ `vector(y, x)` を実行。
3. **結果**: **コピーやムーブが一切発生しない。** 最初からキューの内部にオブジェクトが誕生する。



---

## 3. `emplace` のメリットとデメリット

### メリット
- **パフォーマンスの最大化**: コピーコンストラクタやムーブコンストラクタの呼び出しをスキップできるため、重いオブジェクトを扱う際に高速。
- **記述の簡略化**: `pair` や `struct` を使う場合、型名を明示せずに引数だけを渡せる。

### デメリット・リスク
- **意図しないコンストラクタの呼び出し**: 今回の `vector` のように、複数のコンストラクタを持つ型では、引数の数や型によって予期せぬ初期化が行われる（**強度の型安全性の欠如**）。
- **可読性の低下**: 何を生成しているのかがコードから直感的に分かりにくくなる場合がある。
